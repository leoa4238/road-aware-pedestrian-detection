# 졸업 논문 주제 보고

**가제: 보차 혼용 생활도로에서의 도로 영역 기반 위험 보행자 탐지**

2026-10-10 · 데이터 분석 및 베이스라인 결과

---

## 1. 문제: 생활도로에서는 "보행자가 있다"만으로 위험을 구분할 수 없다

- 생활도로(골목길)는 차 대 보행자 사고 위험과 치명률이 높은 구간이지만, 보도와 차도의 구분(연석)이 없는 경우가 많다.
- AI-Hub `생활도로 객체인식 자율주행 데이터`에서 보행자 10,340명의 발 위치를 도로 영역과 대조한 결과:

| 보행자 위치 | 비율 |
|---|---:|
| 차도 위 | **68%** |
| 보도 위 | 18% |
| 기타 (차량 탑승자, 건물 앞 등) | 14% |

- 기존 ADAS처럼 차량 경로 앞 보행자를 모두 경고하면 생활도로에서는 오경보가 과도하다.
  **어떤 보행자가 실제로 위험한지 구분**하는 것이 필요하다.

## 2. 근거: 해외 데이터 기반 모델은 한국 생활도로의 보행 공간을 구분하지 못한다

- Cityscapes(독일 도로)로 학습한 SegFormer로 도로/보도를 분할한 결과,
  **흰 선으로만 구분된 벽돌 보행로를 차도로 판정**하였다 (예시 이미지 별도 첨부: `figures/zone_2.jpg`).
- 보도로 인식된 영역은 이미지당 0.3~3%에 불과했다.
- → 한국 생활도로 특성을 반영한 도로 영역 인식과 위험 보행자 판단이 필요하다.

## 3. 제안 방법

```
이미지 → YOLO backbone ─┬─→ 도로 영역 head ──→ 도로 마스크
                        ▼                         │
                       Neck ◀─ Road-Guided Attention (제안 모듈)
                        ▼      도로·도로 경계의 특징을 강조
                  탐지 head → 보행자 위치 + 위험 여부
```

- 기존 연구(YOLOP, HybridNets)는 도로 영역을 **별도 결과로 출력**할 뿐 탐지에 활용하지 않는다.
- 제안 모델은 도로 정보로 **보행자 탐지 특징 자체를 강조**하고 위험 보행자를 구분한다.
- 연구실 선행 연구(YOLOv5 + ASAM)와 같은 형식: 기존 탐지 모델 + 제안 attention 모듈, 단계별 비교.

## 4. 현재 결과 (베이스라인)

데이터: AI-Hub 058 전방 카메라 일부(5,501장, 촬영 구간 단위로 train/val/test 분할)
모델: YOLOv8s, 50 epoch, RTX 4060 Ti

|---|---:|
| 보행자 | 0.789 |
| 승용차 | 0.872 |
| 트럭·버스 | 0.778 |

| 개인형 이동장치(PM) | 0.644 |
| **전체** | **0.734** (mAP50-95 0.524) |

## 5. 데이터

| | 이미지 | 보행자 포함 | 보행자 수 |
|---|---:|---:|---:|
| AI-Hub 058 전방 카메라 | 90,035 | 60,659 | 약 17.5만 |

- 야간 21%, 비·안개 33% 포함 → 선행 연구의 주간·맑은 날 편향 한계를 보완할 수 있다.
- 시나리오 코드(교차로 보행자 횡단, 무단횡단, 차도 평행통행 등)와 GPS 메타데이터 제공.

## 6. 일정 (약 3개월)

| 기간 | 내용 |
|---|---|
| 1~2주 | 위험 보행자 정의 확정, 전체 데이터 구축, 베이스라인 확정 |
| 3~5주 | 제안 모듈 구현 및 학습 |
| 6~8주 | 비교 실험 (모듈 유무, 주야간·날씨별, 반복 실험) |
| 9~12주 | 논문 작성 |

선택 확장: GPS 기반 위험 보행자 출현 지점 지도, LiDAR 라벨을 활용한 한국형 도로·보도 분할

## 7. 여쭙고 싶은 점

1. 이 주제와 방향이 학위 논문으로 적절한지
2. "위험 보행자" 정의 기준 (주행 경로까지의 거리 / 도로 가장자리 기준) 에 대한 의견
3. 실험용 GPU 서버 사용 가능 여부
